## 파일 구성

| 파일 | 하는 일 | 고칠 일 |
| --- | --- | --- |
| `index.html` | **학생용 주소** | 없음 |
| `teacher.html` | **교사용(수업자용) 주소** | 없음 |
| `config.js` | 서버 주소 · 클라이언트 ID · 학급 목록 | **★ 반드시 고침** |
| `style.css` | 두 화면이 함께 쓰는 디자인 | 없음 |
| `common.js` | 서버 통신 · 구글 로그인 · 저장소 | 없음 |
| `app.js` | 학생 화면 동작 | 없음 |
| `teacher.js` | 교사 화면 동작 | 없음 |
| `industries.js` | 음악 산업 12분야 자료 (선생님이 주신 파일) | 필요하면 |
| `Code.gs` | 구글 서버 (Apps Script) | **★ 반드시 고침** |
| `Video.gs` | 발표 영상 받기 (Apps Script, 따로 붙이는 파일) | **★ 8단계** |
| `doPost-추가.txt` | Code.gs 에 넣을 여섯 줄 (붙여 넣고 나면 지워도 됨) | 없음 |
| `camtest.html` | 태블릿에서 녹화가 되는지 미리 보는 점검 페이지 | 없음 |

> **왜 한 파일이 아니라 여러 파일인가요?**
> 학생용과 교사용을 **서로 다른 주소**로 나눠 달라고 하셨는데, 두 화면이
> 서버 주소·클라이언트 ID·학급 목록을 똑같이 써야 합니다. 한 파일로 만들면
> 주소를 바꿀 때마다 **두 군데를 고쳐야 하고 한 쪽만 고치는 사고**가 납니다.
> 지금 구조는 `config.js` 한 곳만 고치면 두 화면이 같이 바뀝니다.

## 전체 순서 (한눈에)

```
1단계  구글 클라우드 — 클라이언트 ID 만들기
2단계  스프레드시트 + Apps Script — 서버 만들기          → /exec 주소를 받음
3단계  config.js 고치기                                 → 1·2단계 결과를 붙여 넣음
4단계  깃허브에 올리기                                   → 두 개의 주소가 생김
5단계  클라이언트 ID에 깃허브 주소 등록 (되돌아가기)
6단계  명렬표 넣기
7단계  수업 전 점검
8단계  발표 영상 켜기                                 → 드라이브 권한 + 새 배포
```

각 단계 끝에 **[확인]** 이 있습니다. 확인이 되면 다음으로 넘어가세요.

## 1단계 · 구글 클라이언트 ID 만들기

1. <https://console.cloud.google.com> 접속 → `onixzone@ai.jne.kr` 로 로그인
2. 위쪽 프로젝트 선택 → **새 프로젝트** → 이름 `음악수행평가` → 만들기
3. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**
   - User Type: **내부** (조직 계정이면 이게 뜹니다. 안 뜨면 외부)
   - 앱 이름 `음악 산업 탐구`, 지원 이메일 · 개발자 이메일에 본인 계정
   - 저장하고 계속 → 범위는 건드리지 말고 계속 → 완료
4. **API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - 이름: `음악수행평가 웹`
   - **승인된 자바스크립트 원본**에 아래 두 줄을 추가

     ```
     https://edunity21.github.io
     http://localhost:8000
     ```

     (리디렉션 URI 는 비워 두세요. 쓰지 않습니다.)
   - 만들기 → 나온 **클라이언트 ID** 를 복사해 둡니다.

**[확인]** 복사한 값이 `...apps.googleusercontent.com` 으로 끝나면 맞습니다.

## 2단계 · 스프레드시트와 서버 만들기

1. <https://sheets.new> 로 새 스프레드시트를 만들고 이름을 `음악산업탐구_수집` 으로 바꿉니다.
2. **파일 → 설정 → 시간대**를 `(GMT+09:00) 서울` 로 맞춥니다. ← **꼭 하세요.**
   제출 시각 판단이 여기에 달려 있습니다.
3. **확장 프로그램 → Apps Script** 를 엽니다.
4. `Code.gs` 안의 내용을 전부 지우고, 이 폴더의 `Code.gs` 를 통째로 붙여 넣습니다.
5. 맨 위 ★ 표시된 세 줄을 고칩니다.

   ```javascript
   const CLIENT_ID = '1단계에서 복사한 값';
   const TEACHERS = [ 'onixzone@ai.jne.kr' ];   // 필요하면 줄을 늘리세요
   const ALLOWED_DOMAIN = 'ai.jne.kr';
   ```

6. 저장(💾) → 위쪽 함수 목록에서 **`setup`** 을 고르고 **실행**
   - 권한 요청이 뜨면 → 권한 검토 → 계정 선택 → 고급 → *(안전하지 않은 페이지로 이동)* → 허용
   - 시트 여섯 개(`설정` `제출` `임시저장` `명렬표` `로그` `동료평가`)가 생깁니다.

**[확인]** 스프레드시트로 돌아가 시트 탭 여섯 개와 `설정` 시트의 `전체 / 3-1 … 3-9` 열 줄을 확인하세요.

7. Apps Script 로 돌아와 오른쪽 위 **배포 → 새 배포**
   - 톱니바퀴 → **웹 앱**
   - 설명: `v1`
   - **다음 사용자로 실행: 나**
   - **액세스 권한이 있는 사용자: 모든 사용자** ← 이걸 안 하면 학생이 못 씁니다
   - 배포 → 나온 **웹 앱 URL**(`.../exec` 로 끝남)을 복사

**[확인]** 그 주소를 브라우저 주소창에 그대로 붙여 넣어 보세요.
`{"ok":true,"version":"server v1.0.0 (2026-08-17)","now":"..."}` 가 보이면 성공입니다.

## 6단계 · 명렬표 넣기

1. 교사용 주소 접속 → 구글 로그인 → **명렬표** 탭
2. 엑셀에서 **학번 / 이름 / 비밀번호** 세 칸을 선택해 복사
3. 붙여넣기 칸에 그대로 붙이고 **[명렬표에 넣기]**

```
3301	홍길동	a1b2c3
3302	김철수	d4e5f6
```

- 학번은 **네 자리**여야 합니다. 두 번째 자리로 반을 판별합니다. (`3301` → 3학년 3반 1번)
- 반은 자동으로 채워집니다. 따로 입력하지 마세요.
- 학번이 겹치면 넣기 전에 화면에서 먼저 걸러 냅니다.
- 이미 있는 학번은 **이름·비밀번호만** 바뀌고 계정 고정은 유지됩니다.

**[확인]** 아래 표에 265명이 보이고, `연결된 계정`이 전부 `미연결` 이면 정상입니다.

## 8단계 · 발표 영상 켜기

3차시 발표를 **학생이 태블릿으로 자기 발표를 찍어 내는 방식**으로 바꾸는 부분입니다.
이 단계를 건너뛰어도 나머지는 그대로 돌아갑니다. 영상만 안 될 뿐입니다.

### 8-1 · 태블릿에서 되는지 먼저 봅니다

`camtest.html` 을 깃허브에 함께 올린 뒤,
**학생용 태블릿**으로 `https://edunity21.github.io/musicjob/camtest.html` 을 엽니다.

1단계부터 차례로 눌러 보고, 3단계에서 **1분 예상 용량**이 나오면 됩니다.
8MB 아래면 넉넉합니다. 이 점검 페이지는 서버로 아무것도 보내지 않습니다.

**[확인]** 카메라가 켜지고 시험 녹화가 재생되면 다음으로 갑니다.
안 되면 학교에서 관리 설정으로 카메라를 막아 둔 것이니 정보 담당 선생님께 문의하세요.

### 8-2 · Video.gs 붙이기

1. Apps Script 편집기 왼쪽 **파일 옆 [+] → 스크립트**
2. 이름을 `Video` 로 합니다 (`.gs` 는 저절로 붙습니다)
3. 이 폴더의 `Video.gs` 를 통째로 붙여 넣고 저장(💾)

### 8-3 · Code.gs 에 여섯 줄 넣기

`Code.gs` 의 `doPost` 함수 안에서 아래 줄을 찾습니다.

```javascript
      case 'peer':   return json_(actPeer_(body));
```

**그 바로 아래**에 여섯 줄을 붙여 넣습니다. (`doPost-추가.txt` 에 그대로 있습니다)

```javascript
      case 'videoPing':     return json_({ ok: true, video: VIDEO_VERSION });
      case 'videoInit':     return json_(actVideoInit_(body));
      case 'videoChunk':    return json_(actVideoChunk_(body));
      case 'videoDone':     return json_(actVideoDone_(body));
      case 'videoMine':     return json_(actVideoMine_(body));
      case 'teacherVideos': return json_(actTeacherVideos_(body));
```

저장(💾)합니다.

### 8-4 · 드라이브 권한 받기

함수 목록에서 **`영상_준비`** 를 고르고 **[실행]**.

> **권한 요청이 다시 뜹니다. 이번이 처음이 아니어도 놀라지 마세요.**
> 영상을 드라이브에 저장하려면 **새 권한**이 필요해서 구글이 다시 묻는 것입니다.
> 권한 검토 → 계정 선택 → 고급 → *(안전하지 않은 페이지로 이동)* → **허용**

`음악산업탐구_발표영상` 폴더와 학급별 하위 폴더 아홉 개, `영상` 시트가 생깁니다.

### 8-5 · 새 배포 ← **이걸 안 하면 아무것도 안 됩니다**

**[배포] → [배포 관리] → 연필(✏) → 버전 [새 버전] → [배포]**

새 배포를 만들지 마세요. 주소가 바뀝니다. **반드시 [배포 관리] 로 버전만 올립니다.**

### 8-6 · 확인

함수 목록에서 **`영상_점검`** 을 고르고 **[실행]** → **[실행 로그]** 를 봅니다.

```

■ 드라이브 : 됩니다 ✅
■ 「영상」 시트 : 있습니다 ✅
```

셋 다 ✅ 면 끝났습니다. 하나라도 ❌ 면 그 줄이 무엇을 하라고 알려 줍니다.

**[확인]** 교사용 주소에 들어가 **[발표 영상]** 탭이 보이고,
표에 그 학급 학생 이름이 늘어서면 됩니다.

### 화질을 바꾸려면

`config.js` 아래쪽을 고칩니다.

```javascript
const VIDEO_SECONDS = 60;      // 몇 초까지 찍을지
const VIDEO_WIDTH   = 640;     // 그림 크기
const VIDEO_HEIGHT  = 480;
const VIDEO_BPS     = 600000;  // 초당 자료량. 1분 ≒ 4.5MB
```

`VIDEO_BPS` 를 900000 으로 올리면 또렷해지는 대신 용량이 1.5배가 됩니다.
400000 으로 내리면 가벼워지는 대신 흐려집니다. **얼굴과 목소리만 알아보면
되는 발표 영상이라 600000 을 기본으로 두었습니다.**

## 입장과 제출, 두 개의 자물쇠

자물쇠가 **두 개** 있습니다. 헷갈리기 쉬운 지점이라 먼저 봐 주세요.

| | **입장** | **제출** |
| --- | --- | --- |
| 무엇을 막나 | **로그인 자체** | [지금 제출하기] |
| 닫히면 학생은 | 화면에 들어오지 못함 | 들어와 쓸 수는 있으나 못 냄 |
| 닫히면 서버 저장은 | **멈춤** (기기에는 남음) | 계속됨 |
| 언제 여나 | 수업 시작할 때 | 조사를 시작할 때 |

**입장이 닫히면 제출도 자동으로 닫힙니다.** 반대는 아닙니다.
1차시처럼 "들어와서 쓰기만 하고 내지는 않는" 시간이 있기 때문입니다.

수업 시간이 지나면 로그인도 서버 저장도 멈춥니다. 집에서 이어 쓴 내용은 서버에
남지 않으므로, 운영안의 **과제형 수행평가 금지** 요건을 충족합니다.

### 학생이 보는 화면

| 상황 | 학생 화면 |
| --- | --- |
| 입장 닫힘 | 학번 네 자리를 치는 순간 **"선생님이 열어 주실 때까지 기다려 주세요"** — 비밀번호를 넣기 전에 알려 줍니다 |
| 입장 시작 전 | "수업은 10:20 부터 시작합니다" |
| 수업 중 · 제출 닫힘 | 쓰기 가능, 제출 단추만 잠김 |
| 수업 중 · 제출 열림 | "제출 열림 · 남은 시간 24:31" |
| 수업 종료 10분 전 | 띠에 "수업 종료까지 09:58" 이 함께 붙음 |
| 수업 종료 | 마지막 저장을 한 번 하고 **모든 입력칸이 잠김** |

> 입장이 닫혀 있을 때 시도한 로그인은 **비밀번호 실패 횟수에 넣지 않습니다.**
> 쉬는 시간에 몇 번 눌러 본 학생이 정작 수업 시간에 잠기는 일을 막기 위해서입니다.
> 교사 계정은 화면 점검을 위해 입장 시간과 상관없이 통과합니다.

## 수업 중 조작 (차시별)

모두 **수업 통제** 탭에서, 그 학급 줄의 단추 하나로 합니다.

### 1차시 — 분야 정하기
| 시점 | 누를 단추 |
| --- | --- |
| 수업 시작 | **[수업 시작]** — 50분 입장 허용, 제출은 닫힘 |
| 정리 | **[수업 종료]** |

학생은 [저장하기]만 눌러도 서버에 보관됩니다.
**제출 현황** 탭의 `작성 중` 숫자로 저장 여부를 확인하세요.

### 2차시 — 조사하고 제출
| 시점 | 누를 단추 |
| --- | --- |
| 수업 시작 | **[수업 시작]** |
| 전개 1 시작 | **[제출 열기]** — 25분 |
| 정리 | **[제출 닫기]** → 미제출 명단 확인 → **[수업 종료]** |

바쁘면 **[수업+제출 함께 열기]** 하나로 끝내도 됩니다.

### 3차시 — 발표 영상 찍기와 동료 평가

한 시간을 둘로 나눕니다. **앞은 찍고, 뒤는 함께 봅니다.**

| 시점 | 누를 단추 · 할 일 |
| --- | --- |
| 수업 시작 | **[수업 시작]** — 이때부터 카메라가 켜집니다 |
| 전개 1 (약 20분) | 학생이 [발표 준비] 탭에서 각자 찍고 **[이 영상 내기]** |
| 전개 2 (약 20분) | 교사용 **[발표 영상]** 탭 → **[첫 번째부터 틀기]** → 한 편 보고 → **[다음 발표자 →]** |
| 정리 | 안 낸 사람 확인 → **[수업 종료]** |

**찍는 동안 교실이 시끄러워집니다.** 서른 명이 동시에 말하면 서로 목소리가 섞입니다.
모둠별로 차례를 두거나, 복도·음악실 뒤편·빈 교실로 흩어 보내는 편이 낫습니다.
찍는 데는 1분이면 되므로 모둠을 넷으로 나눠 5분씩 돌려도 시간이 남습니다.

**학생이 보는 순서**
[발표 준비] 탭 → [카메라 켜기] → [● 녹화 시작] → 60초 뒤 저절로 멈춤 →
한 번 보고 → 마음에 안 들면 [다시 찍기] → 괜찮으면 **[이 영상 내기]**

**거울처럼 보기** — 카메라가 잡은 그대로 보여 주면 「남이 보는 나」라서 어색합니다.
손을 오른쪽으로 들면 화면에서는 왼쪽으로 움직이니 더 그렇습니다. 그래서 셀카처럼
좌우를 뒤집어 보여 주고, 학생이 화면에서 껐다 켤 수 있게 두었습니다.

`config.js` 에 손잡이가 둘 있습니다.

| 설정 | 하는 일 |
| --- | --- |
| `VIDEO_MIRROR_DEFAULT` | 처음 들어왔을 때 거울이 켜져 있을지 (기본 `true`) |
| `VIDEO_MIRROR_SAVE` | **저장되는 영상까지 뒤집을지** (기본 `true`) |

`VIDEO_MIRROR_SAVE = true` 면 **학생이 화면에서 본 그대로 저장됩니다.**
보이는 것과 내는 것이 같아서 학생이 헷갈리지 않습니다.
대신 옷이나 뒤쪽 칠판에 글씨가 있으면 **그 글씨가 거꾸로 보입니다.**
발표 때 종이나 그림을 들어 보이게 하실 생각이면 `false` 로 두세요.

> 켜고 끄는 것은 학생 몫이지만, **찍는 도중에는 잠깁니다.** 중간에 바뀌면
> 앞뒤가 섞인 영상이 되기 때문입니다.

> 아주 오래된 태블릿은 화면만 뒤집을 수 있습니다(그림판 신호 뽑기 미지원).
> 그런 기기에서는 화면에 「이 태블릿은 화면만 뒤집을 수 있습니다」 라고 알려 주고,
> 영상은 안 뒤집힌 채로 저장됩니다. 나머지 기능은 그대로 됩니다.

> **[이 영상 내기] 를 눌러야 선생님께 옵니다.** 찍기만 하고 안 낸 학생이 꼭 나옵니다.
> [발표 영상] 탭의 `영상 냄` 숫자로 확인하고, 정리 5분 전에 한 번 짚어 주세요.

**동료 평가**는 지금까지와 같습니다. 교실 화면으로 영상을 함께 본 뒤,
학생이 자기 태블릿 [동료 평가] 탭에 발표자 학번을 적고 씁니다.
한 편 틀고 → 적을 시간 30초 → 다음 편, 이 흐름이 무난합니다.

**결시자·다시 찍기** — 영상은 학생당 마지막에 낸 것 하나만 남습니다.
수업 시간만 열려 있으면 몇 번을 다시 내도 됩니다. 예전 것은 저절로 지워집니다.

**낸 영상은 어디에 있나** — 선생님 구글 드라이브의
`음악산업탐구_발표영상 / 3-1` 처럼 학급별 폴더에 `3-1_3101_홍길동_20260910_1042.mp4`
로 쌓입니다. `영상` 시트에 학생당 한 줄로 링크가 남습니다.

### 결시자 재작성
1. **손으로 세밀하게 고치기** 를 펼칩니다
2. 그 학급 줄의 `다시 내기` 를 **허용** 으로 → [바뀐 설정 저장]
3. **[수업+제출 함께 열기]**
4. 끝나면 `다시 내기` 를 **금지** 로 되돌립니다

### 시간 길이를 바꾸려면
`teacher.js` 맨 위 두 줄을 고치세요.

```javascript
const LESSON_MINUTES = 50;   // [수업 시작] 이 여는 시간
const SUBMIT_MINUTES = 25;   // [제출 열기] 가 여는 시간
```

## 세부 동작 설명

### 학생 화면이 지키는 것
- **자동 저장** — 글자를 칠 때마다 기기에 저장(0.6초 뒤), 서버에는 2초 모았다가 보냅니다.
  같은 내용이면 보내지 않고, 15초에 한 번을 넘지 않습니다. 탭을 닫을 때 한 번 더 보냅니다.
- **기기가 고장 나도** — 다른 태블릿에서 같은 계정으로 들어오면 서버 임시저장본을 불러옵니다.
- **시계 조작 불가** — 열림/마감 판단은 전부 서버가 합니다. 화면의 남은 시간은 서버 시각을 따릅니다.
- **잠금** — 제출을 마치면 입력칸이 읽기 전용이 됩니다. 교사가 `다시 내기`를 켜면 풀립니다.

### 서버가 거부하는 경우 (모두 `로그` 시트에 남습니다)
| 사유 | 언제 |
| --- | --- |
| `DOMAIN_DENIED` | `@ai.jne.kr` 이 아닌 계정 |
| `NOT_IN_ROSTER` | 명렬표에 없는 학번 |
| `NAME_MISMATCH` | 학번과 이름이 안 맞음 |
| `WRONG_PASSWORD` | 비밀번호 틀림 (5번 틀리면 5분 잠금) |
| `ACCOUNT_MISMATCH` | 그 학번은 다른 계정에 고정되어 있음 |
| `DUPLICATE_ACCOUNT` | 그 계정은 다른 학번으로 이미 들어옴 |
| `ENTRY_CLOSED` | 수업이 열려 있지 않음 (로그인·저장 모두 거부) |
| `ENTRY_BEFORE` | 입장 시작 시각 전 |
| `ENTRY_AFTER` | 수업 종료 시각 지남 |
| `BEFORE_OPEN` / `AFTER_CLOSE` / `CLOSED` | 제출 시간이 아님 |
| `ALREADY_SUBMITTED` | 이미 냈는데 다시 내기가 꺼져 있음 |

### 시트 구성
| 시트 | 내용 |
| --- | --- |
| `설정` | 학급별 **입장** 허용·시작·마감, **제출** 허용·다시내기·시작·마감, 공지. 학급 칸이 비면 `전체` 줄을 따릅니다. |
| `제출` | 제출본 누적. 9문항이 각각 열로 펼쳐져 있어 그대로 채점표가 됩니다. |
| `임시저장` | 작성 중 내용. **학생당 한 줄, 덮어쓰기.** 미제출자 확인 자료. |
| `명렬표` | 학번·이름·반·비밀번호·연결된 계정·최근 접속 |
| `로그` | 거부·성공 기록 |
| `동료평가` | 3차시 입력. 평가자-발표자 한 쌍당 한 줄. |

## 문제가 생기면

| 증상 | 원인과 해결 |
| --- | --- |
| 로그인 단추가 안 보임 | 클라이언트 ID 오타. `config.js` 확인. |
| `400: invalid_client` | 승인된 자바스크립트 원본에 `https://edunity21.github.io` 없음. |
| 저장은 되는데 서버 저장 실패 | `/exec` 주소 오타, 또는 배포 액세스 권한이 `모든 사용자`가 아님. |
| 코드를 고쳤는데 그대로임 | Apps Script **[배포 관리] → 연필 → 새 버전**을 안 눌렀음. |
| 시간이 이상함 | 스프레드시트 시간대가 서울이 아님. |
| 학생이 로그인이 안 됨 | 그 학급의 **입장**이 닫혀 있음. [수업 시작]을 누르세요. |
| 제출이 안 열림 | 입장이 열려 있는지 먼저 보세요. 입장이 닫히면 제출도 닫힙니다. |
| 설정 시트 머리글이 예전 것 | 스프레드시트 메뉴 `음악 수행평가 → 설정 시트 다시 만들기` |
| 무엇이 도는지 모르겠음 | 학생 화면 F12 콘솔에 버전이 찍힙니다. 서버는 `/exec` 주소를 직접 열면 버전이 보입니다. |

### 발표 영상

| 증상 | 원인과 해결 |
| --- | --- |
| 무엇이든 이상하다 | Apps Script 에서 **`영상_점검`** 을 먼저 실행하세요. 무엇이 빠졌는지 알려 줍니다. |
| 교사 화면에 「서버에 영상 기능이 아직 붙지 않았습니다」 | 8-3(여섯 줄) 또는 8-5(새 배포)를 안 했습니다. |
| 학생 화면에 「이 태블릿에서는 앱 안에서 찍을 수 없습니다」 | 그 기기가 녹화를 지원하지 않거나, 학교 관리 설정이 카메라를 막았습니다. `camtest.html` 로 확인하세요. |
| 카메라 허용을 눌렀는데 안 켜짐 | 다른 앱이 카메라를 쓰고 있습니다. 그 앱을 닫고 화면을 새로 고칩니다. |
| 「보내지 못했습니다」 | 와이파이가 흔들린 것입니다. 찍은 영상은 그대로 있으니 **[이 영상 내기]** 를 한 번 더 누르면 됩니다. |
| 「수업 시간에만 찍을 수 있습니다」 | 그 학급의 **입장**이 닫혀 있습니다. [수업 시작] 을 누르세요. |
| 재생창에 「처리 중」 | 구글이 영상을 준비하는 중입니다. 30초쯤 뒤 다시 열면 나옵니다. |
| 재생창이 비어 있음 | 교사 계정으로 구글에 로그인되어 있어야 합니다. [새 탭에서 열기] 로도 됩니다. |
| 드라이브에 조각 파일이 쌓임 | 업로드가 끊긴 자리입니다. `영상_임시정리` 를 실행하면 치워집니다. |

## 발표 영상과 개인정보

학생 얼굴과 목소리가 담긴 영상이라 글 답안과 다르게 다뤄야 합니다.

- **수집 목적** — 생활화 영역 수행평가([9음03-02]) 발표 채점
- **보관 위치** — 담당 교사 구글 드라이브(학교 계정). 학생끼리는 서로 볼 수 없습니다.
- **보관 기간** — 성적 확정 뒤 일괄 삭제.
  Apps Script 함수 **`영상_모두삭제`** 를 실행하면 한 번에 지워집니다.
- **동의** — 학기 초 동의서에 *수업 활동 촬영·녹화* 가 들어 있는지 확인하세요.
  없으면 별도 동의를 받는 편이 안전합니다.
- 영상은 **수업 시간에만** 찍히고 보내집니다. 집에서는 아무것도 올라가지 않습니다.
  과제형 수행평가 금지 요건은 그대로 지켜집니다.

### 버전 표시가 있는 곳
- 학생 화면: 로그인 화면 아래 + 콘솔
- 교사 화면: 로그인 화면 아래 + 상단 `서버 v1.0.0 · 시트 연결됨`
- 서버: `/exec` 주소를 직접 열기, 또는 스프레드시트 메뉴 `음악 수행평가 → 버전 확인`
- 영상: Apps Script 에서 `영상_점검` 실행

## 알아 두실 점

- **구글 로그인 스크립트만** `accounts.google.com` 에서 불러옵니다. 구글 로그인은 다른 곳에서
  받아올 수 없습니다. 나머지(폰트)는 `cdn.jsdelivr.net` 만 씁니다. 외부 UI 라이브러리는 없습니다.
- **Apps Script 실행 할당량** — 한 학급 30명이 20초마다 상태를 확인합니다. 이 확인은 가볍게
  만들어 두었습니다(8초 캐시, 로그인 확인 생략). 9개 학급을 하루에 몰아서 하지 않는 한 여유롭습니다.
  걱정되면 `config.js` 의 `POLL_SECONDS` 를 30~40으로 올리세요.
- **관련 학과** 목록은 자료집에 없던 내용이라 `config.js` 의 `MAJORS` 에 따로 뺐습니다.
  확인하시고 고치거나, 통째로 지우면 화면에서 사라집니다.
- 학생 화면은 **가로 360px 스마트폰**부터 맞췄고, 터치 영역은 44px 이상입니다.
  교실 프로젝터(1200px 이상)에서는 글자가 자동으로 커집니다.
